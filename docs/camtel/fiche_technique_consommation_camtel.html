4. Consommation mesurée (used so far)

Mesures réalisées le 20 octobre 2026 sur la stack Docker de production (Nginx + API Nest + PostgreSQL 16), au repos puis avec appels santé HTTP. Une instance applicative = un front + une API + une base.

Ressource Consommation observée (1 instance)
Processeur (CPU) Au repos : < 5 % d’un vCPU pour l’API ; PostgreSQL ≈ 0 % ; Nginx ≈ 0 %.
Au démarrage / pics légers : API jusqu’à ≈ 30 % d’un vCPU (courte durée).
Profil métier : charge faible à modérée (JSON / pages web, pas de calcul intensif).
Mémoire RAM API Node (processus) : ≈ 95–130 Mo (repos → après requêtes).
PostgreSQL : ≈ 35–40 Mo au repos.
Nginx (front) : ≈ 4–5 Mo.
Total observé ≈ 140–175 Mo pour 1 instance complète au repos / usage léger.
Stockage disque Images Docker (empreinte installée) :
— API : ≈ 588 Mo · Front/Nginx : ≈ 77 Mo · PostgreSQL 16 : ≈ 420 Mo
→ ≈ 1,1 Go pour les images de la stack.
Données métier (base synchronisée, schéma + tables vides) : ≈ 8 Mo (volume Postgres ≈ 47 Mo avec fichiers système).
Fichiers front (build) : ≈ 2,7 Mo.

Ces chiffres correspondent à la consommation actuelle de l’application (empreinte réelle mesurée). La croissance des données métier, des logs et le nombre d’entreprises hébergées feront évoluer surtout le stockage et, dans une moindre mesure, la RAM. Le dimensionnement commercial du VPS reste à la proposition de CAMTEL.
